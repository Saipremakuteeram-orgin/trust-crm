# Fix missing logo in report PDF headers

## Problem
The trust logo is missing from PDF reports generated by two endpoints in `backend/src/routes/reports.js`:
- `POST /api/reports/export/pdf`
- `POST /api/reports/generate` (when `format === 'pdf'`)

Both endpoints draw their own inline header instead of using the centralized `drawPdfHeader` function from `backend/src/lib/reportBranding.js`, which includes the logo, trust name, tagline, and proper branding.

## Root Cause
`reports.js` does not import or use `drawPdfHeader`. Other report generators (`exports.js`, `monthlyReport.js`, `scheduledReports.js`, `whatsappReportGenerator.js`) correctly use `drawPdfHeader` and include the logo.

## Fix

### 1. Add import in `backend/src/routes/reports.js`
Add `drawPdfHeader` import from `@/lib/reportBranding`.

### 2. Replace inline header in `POST /api/reports/export/pdf` (lines ~208-212)
Replace:
```js
doc.fontSize(20).font('Helvetica-Bold').text('Trust CRM', 40, 40);
doc.fontSize(11).font('Helvetica').text(`Transaction Report — ${label}`, 40, 65);
doc.fontSize(9).fillColor('#666666')
  .text(`Generated by: ${profile?.full_name || 'Unknown'}  |  Date: ${new Date().toLocaleDateString('en-IN')}`, 40, 82);
doc.moveTo(40, 100).lineTo(815, 100).strokeColor('#e5e7eb').stroke();
```

With:
```js
const headerY = drawPdfHeader(doc, {
  subtitle: `Transaction Report — ${label}`,
  generatedBy: profile?.full_name || 'Unknown',
  date: new Date().toLocaleDateString('en-IN'),
});
```

Update the table header start Y from hardcoded `112` to use `headerY`.

### 3. Replace inline header in `POST /api/reports/generate` PDF block (lines ~364-368)
Same replacement as above.

### 4. Update page-break logic
In both PDF blocks, when adding a new page during row iteration, the current code resets `rowY = 40`. After switching to `drawPdfHeader`, new pages should also call `drawPdfHeader` again so subsequent pages keep the branding. Add `drawPdfHeader(doc, { subtitle, generatedBy, date })` inside the `doc.addPage()` branch and return the new Y.
